# たいせん（対戦）のつなぎかた

対戦は **Supabase Realtime** を中継に使います。データベースも認証も使いません。
チャンネル（broadcast と presence）だけです。

中継は **kanji_go と 同じ Supabase プロジェクト**（`iyceaspukufevktabmvy`）です。
2026-10-03 に「kanjigo と 同じ 環境を 使って いい」と 決まりました。URL と anon キーは
`src/lib/versusConfig.ts` に 既定値として 入って いるので、**設定しなくても 対戦は 動きます**。

---

## 待合室は 混ざらない

中継の チャンネルは 名前ごとに 別です。このゲームは `nexmax-kanji-lobby`、kanji_go は
`kanjigo-lobby-all` で 待つので、相手を さがして いる 人どうしが 混ざる ことは ありません。
anon キーは **公開前提の 鍵**（ブラウザの バンドルに 必ず 入る。kanji_go も そのまま 入れて いる）なので、
ソースに あって 問題 ありません。

## 止まった とき

無料枠の プロジェクトは、しばらく 使われないと **一時停止** します（ホスト名が DNS から 消え、
対戦の 画面は「つながりません」に なる）。2026-10-03 にも 止まって いたので 再開 しました。
Supabase の ダッシュボード（または Supabase MCP の restore_project）で 再開 できます。
止まらない ように、kanji_go の DB に 読むだけの 表 `public.keepalive`（1行）を 置き、
2つの keep-alive が 別の 日に それを 読みます（2026-10-03）。片方の スケジュールが 止まっても 平気です。

| リポジトリ | ワークフロー | 日 |
| --- | --- | --- |
| kanji_go | `.github/workflows/supabase-keepalive.yml` | 1・4・7…日 |
| このリポジトリ | `.github/workflows/relay-keepalive.yml` | 2・5・8…日 |

`/rest/v1/` を 叩くだけの ping は「使って いる」と 数えられず、2026-09-25 に 止まりました。
表を 消すと keep-alive が 失敗に なるので、消さないで ください。

## 別の プロジェクトに つなぐ とき

ビルド時に 2つの 変数を 渡すと、既定値の かわりに それを 使います（フォーク向け）。

| 名前 | 中身 |
| --- | --- |
| `VITE_SUPABASE_URL` | `https://xxxxx.supabase.co` |
| `VITE_SUPABASE_ANON_KEY` | anon public キー |

`.github/workflows/deploy.yml` は リポジトリの Variables から 渡す ように なって います
（未設定なら 空なので 既定値が 使われる）。ローカルでは `.env.local` に 書きます（`.gitignore` 済み）。

## 対戦の中身

- **同じ漢字を12字**、両方が書きます。ホスト側が選んで HANDSHAKE で配ります
- 一発で書ければ 1.5倍、1回まちがえて 1.1倍、2回で 0.8倍
- **3回まちがえると、自分が ダメージを受けます**（相手ではなく）
- HP 100。先に 0 にしたほうが勝ち

### 武器の差は2割まで

武器の攻撃力は効きますが、**最大でも2割**しか変わりません（`MAX_WEAPON_BONUS = 0.2`）。

ジェムを貯めた人が自動的に勝つ対戦は、学習ゲームとして意味がありません。
**コレクションの薄い人でも、漢字が書ければ勝てる**必要があります。
実力の差（1.5倍 対 0.8倍 ＝ 約1.9倍）が武器の差（最大1.2倍）を常に上回るようにしてあります。

### コンボ と なかまの わざ（2026-10-04、設計 11 §7）

- **コンボ**: 一発で 書き続けると 1コンボ ＋5%、最大 ＋25%（`rules.ts` `versusComboBonus`）。画面の ＋% と 同じ 数字
- **なかまの わざ**: 書いて ゲージを ためる（一発 ＋2・1回ミス ＋1、満タン 6）。相手にも カットインが 見える
  - 自分の 書く ことだけ 変える わざは その まま: ちから（つぎの こうげき ×1.4）・コンボ（＋2、2字 切れない）・
    おちつき（ミスを 2回 なかった ことに）・ヒント（書きじゅんを 見ても へらない）
  - HP に かかわる わざは「相手の つぎの こうげきを へらす」形: いやし −15・まもり 0。**こうげきした 側が** へらして
    HIT の ダメージに 入れて 送る（`warded` も 送る）。わざと こうげきが 通信で 行きちがっても、両方の 画面の HP が そろう
  - ★の 差は 小さく（★5 で ★3 の 1.1倍まで）。武器 × ★ で 1.35倍を こえない（`rules.test.ts`）
- 通信: `SKILL` イベント（`{ kind, card, ward }`）。古い 版は 知らない イベントを 無視する（ward は 効かないが、HP は ずれない）
- CPU も なかまの わざを 使う（CPU の なかまの わざ。まもり・いやしは プレイヤーの つぎの こうげきを へらす）

### へやの ルール（2026-10-15）

とみさん「N5,N4,N3とステージごとの漢字で出題の絞り込みができるようにしてほしい。武器防具、レベル、ガチャキャラサポートありなしを
チェックボックスで変更できるように。これはルームを作る人が最初に決められます。ルームにはそれが表示されています」。

- **ともだちと → へやを つくる（ルールを きめる）** で、へやを 作る 人が 先に きめる（`RulesSheet.tsx`・`roomRules.ts`）。
  - 出題の はんい: **N5・N4・N3**（1つ以上）と **ステージ**（ぜんぶ／章ごと／話ごと）。2つは 重ねて しぼる（N4 だけ ＋ 1章 → 1章の N4 の 字）。
  - **🗡️ 武器・防具**: ぶきの こうげき（＋2割まで）・たての まもり（1割まで へらす）・よろいの HP（＋10まで）。
  - **⭐ レベル**: ネクマックスの レベルで HP（＋15まで）。
  - **🤝 なかま（ガチャの キャラ）**: なかまの 絵と わざ。なしなら 両方 ネクマックス、あいては 色ちがい（2P、`img/versus/nexmax_2p*.webp`）。
  - 前に きめた ルールを この 端末に おぼえる（`nexmax-versus-room-rules`）。
- ルールは ホストの **PROFILE と HANDSHAKE** に のって 届く（`data.rules`）。ともだちは 待って いる あいだに ルールが 見え、
  へやの 画面と VS の 画面に「📜 へやの ルール」の カードが 出る。
- 強さは **それぞれが 自分の 数字を PROFILE で 送る**（`profile.power`: 武器・まもり・よろいの HP・レベルの HP。受けとる 側で 上限に そろえる）。
  どれが 効くかは ルールで きめる。まもりは **こうげきした 側が** へらして HIT に 入れる（わざの ward と 同じ。両方の HP が そろう）。
- 「書ける ほうが 勝つ」は そのまま: ぜんぶ ありの いちばん 強い 人が 2つ ミスで 書いても、なにも ない 人が きれいに 書く ほうが 先に 勝つ（`roomRules.test.ts`）。
- ランダムの たいせんと CPU は きまった ルール（N5〜N3・ぜんぶの ステージ・武器・防具 あり・レベル なし・なかま あり）。
  1章の 字から 出る のは 前と おなじ。

### たいせんの 見た目（2026-10-15）

とみさん「対戦画面のUIをもう少しテイストに合わせて、かつスマブラのように盛り上がる感じで。Codexで画像を作ってもいいです」。

- **ぶたい**: 町の 上の まるい ぶたい（`img/versus/vs_arena.webp`、Codex）。ロビー・けっか・たたかいの 背景。ロビーでは 青と 赤の サーチライトが ゆれる。
- **VS**: 青（1P じぶん）と 赤（2P あいて）の 面が ななめに 分かれて とびこみ、集中線が 走る。2人が どんと 着地 →「VS」が 光って ぶつかる → 3・2・1・書け！（`VersusFx.tsx` `VsSplash`）。
- **ランクの メダル**: 石・銅・銀・金（`img/versus/rank_*.webp`、Codex）。ヘッダー・VS の 名札・けっかの レート。ランクアップで メダルが 回って 出る。
- **たたかい**: HP が 4分の1 より 下で 赤く 光る（ピンチ）。どちらかが たおれると 白く 光って「しょうぶ あり！」→ けっか。
- **けっか**: 勝ったら 金の「勝ち！」と 紙ふぶき、勝った ほうに スポットライト、負けた ほうは 少し 暗く。
- 動きを 少なく する 設定では、動きは ぜんぶ 止めて 同じ 画面を 出す（`useStill`）。

### レート

1000 から始まり、勝敗で ±（K=32）。**800 より下がりません** — 連敗した学習者が
下がるだけの数字を見続けることにならないように。

相手のレートは中継では分からない（アカウントを持たない設計なので）ため、
**同格の相手と戦ったものとして計算**します。

## 制限

- 中継はメッセージを運ぶだけで、**勝敗を検証しません**。改造されたクライアントは嘘のダメージを
  送れます。友達どうしで遊ぶ想定なので、いまはこれで足ります。
  順位表を公開するなら、サーバ側の検証が要ります
- 待合室は1つです。レベル（N5/N4/N3）で分けていません
  （分けると、待っている人がいない可能性が高くなるため。kanji_go の判断を引き継いでいます）
