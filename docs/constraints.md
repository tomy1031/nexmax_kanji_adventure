# 制約と好みの台帳

とみさんが口にした制約・好みを、言われた日付とともに残す。
**作業を始める前に必ず読む。** セッションをまたいで記憶は残らないので、ここが唯一の引き継ぎ。

新しく制約を聞いたら、その場でここに足す。消すときは「いつ・なぜ外したか」を書いてから消す。

## 進めかた

- **PR とマージは Claude が行う**（2026-09-17）。とみさんは許可を出す側で、GitHub の操作はしない。
  検査（typecheck / lint / test / build）が緑になったら、PR を立てて `main` へマージするところまで進める。
  `main` へ入ると GitHub Pages へ自動で出る（`.github/workflows/deploy.yml`）。
- 確認をお願いするときは、**とみさんが見られる形（公開URL）まで進めてから**。
  動くかどうかの確認をさせない。見てほしいのは中身（遊びとして面白いか、学べるか）。
- ステージや仕組みを足す・並べ替えるときは、**並びを before → after で書いてから**着手する。
  並びは「足した順」ではなく「前提が揃う順」。

## このゲームの決まりごと

- **書取り10回で漢字を入手**（2026-09-16）。これは変えない。
  「戦闘に行くまでに何字要るか」は別の話で、こちらは調整してよい（いまは3字）。
- **ガチャは10連**（2026-09-17 の指摘で単発から変更）。
- **ネクマックスの個体**はステージクリアと、デイリータスクで貯めたジェムのガチャで手に入る。
- **武器は漢字の合成で作る。** 実在する熟語が非語より強いこと
  （関係ない3字が正しい2字に勝たないこと）はテストで固定してある。
- **対戦は kanji_go から移植したもの**を使う。ただし **kanji_go の Supabase の鍵は移さない**
  （ロビーが混ざる・他プロジェクトの資源）。理由は `docs/versus.md`。
